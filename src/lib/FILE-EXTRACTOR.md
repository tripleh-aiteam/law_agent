# File Extractor (v1)

The file extractor turns user-uploaded documents into plain text for the case-narrative pipeline. Supported formats are **PDF** (parsed via `pdf-parse`; per-page text concatenated, page count returned), **DOCX** (parsed via `mammoth.extractRawText`; any structural warnings from mammoth are surfaced back to the caller), and **plain text** files (`.txt` and `.md`, decoded as UTF-8 with BOM stripping). Image-only/scanned PDFs are detected heuristically — when the extracted text is under 50 characters but the file has pages, a warning instructs the user to paste the text manually because OCR is not run in v1. Encrypted or corrupted PDFs do not throw a 500; they return empty text with a descriptive warning. HWP and HWPX files are **explicitly not supported in v1**: they return successfully with empty text and a bilingual Korean/English warning asking the user to re-upload as PDF. Anything else (e.g. `.rtf`, `.odt`, images) is rejected with an `Unsupported file type` error which the route catches and converts into a per-file warning entry rather than failing the whole request.

Hard limits are **20 MB per file**, **5 files per request**, and **40 MB total per request**, enforced before any parsing work begins; violations return HTTP 413. The upload route is `POST /api/upload` (multipart/form-data, field name `files`) and always returns `{ files: ExtractedFile[] }` in request order. The planned upgrade path for HWP is a small **Python sidecar service** wrapping `hwp5` / `pyhwpx` (or a headless LibreOffice conversion step) that the Node route calls over HTTP; once available, the `extractFromBuffer` dispatcher will route HWP buffers to that service instead of returning the warning. OCR for scanned PDFs is a separate planned upgrade — likely Tesseract or a hosted OCR API — gated behind the same dispatcher so the public response shape stays stable.
